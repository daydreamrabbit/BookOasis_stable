# 폴더 감시

설정 → **스캔 스케줄 & 대기열** → 각 라이브러리의 **폴더 감시 설정**에서 켭니다.
기본값은 OFF입니다. 일반/성인 도서 라이브러리를 지원하며, 오디오북·영상 전용
스캐너는 별도의 트랙 삭제 정책을 사용하므로 이 감시 기능에 연결하지 않았습니다.

## 저장소별 설정

### 카테고리 간 이동과 읽기 기록

같은 서재 유형의 감시 중인 카테고리 사이에서 파일이 이동하면, 새 항목을
등록하기 전에 기존 도서 ID의 경로와 카테고리를 변경합니다. 읽기 위치,
책갈피, 형광펜, 메모는 같은 도서 ID에 연결된 상태로 유지됩니다.
이동 전 양쪽 감시의 기준 목록이 저장되어 있어야 합니다. 삭제 자동 반영을
켜지 않아도 이동 확인은 실행됩니다. 원래 위치에서 먼저 누락을 처리한 경우를
위해 누락 파일 식별 정보는 30일간 보관합니다.

- 로컬 디스크: 장치·inode, 크기와 수정 시간으로 확인합니다.
- rclone: 같은 리모트 안에서 고유 파일 ID, 크기와 수정 시간이 일치해야 합니다.
- 공개 Drive: 고유 파일 ID, 크기와 수정 시간으로 확인합니다.
- 원래 파일이 남아 있는 복사/하드링크, 여러 후보, 이미 등록된 새 위치는 자동 병합하지 않습니다.
- 식별값을 제공하지 않는 NAS/rclone 저장소, 파일시스템을 넘는 이동,
  일반↔성인 서재 이동은 자동 기록 승계 대상이 아닙니다.
- 원본 경로 연결 오류는 삭제나 이동으로 간주하지 않고 작업을 보류합니다.

원본 파일을 프로그램이 이동/삭제하는 기능이 아니라, 확인된 파일 이동을 DB에 반영하는 기능입니다.

| 저장소 | 선택 | 비고 |
| --- | --- | --- |
| 로컬 디스크 | 자동 또는 로컬 | watchdog 이벤트 + 주기적 전체 목록 재확인 |
| SMB/NFS/NAS | 목록 비교 | 서버에서 보이는 마운트 경로를 사용 |
| rclone | 자동 또는 rclone 원격 목록 비교 | 자동은 각 마운트 경로를 개별 연결합니다. 수동은 라이브러리 경로 순서대로 대응하는 `remote:folder`를 한 줄씩 입력합니다. |
| Google Drive 공개 폴더 | 자동 | 기존 `GDRIVE_API_KEY` 또는 `GOOGLE_API_KEY` 필요 |
| 인증이 필요한 Drive | rclone | 기존 rclone 인증/마운트 재사용 |

예: 라이브러리 경로 `/data/books`가 `mydrive:Books`의 마운트라면 원격 경로에도
`mydrive:Books`를 입력합니다. 리모트 설정은 기존 rclone.conf를 사용합니다.
직접 `remote:folder`만을 라이브러리 경로로 등록하는 기능은 아닙니다.
마운트 목록과 원격 목록의 경로·크기·수정 시간이 다르면 스캔을 보류합니다.

Google Drive의 현재 직접 연결은 공개 폴더/API 키 방식입니다. OAuth 인증을
필요로 하는 Changes API의 변경 토큰은 사용하지 않습니다. 모든 페이지의
`files.list` 결과(하위 폴더 포함)를 비교합니다. 인증/조회 오류나 불완전한
목록을 빈 폴더로 처리하지 않습니다. HTML 파싱으로 조용히 대체하지 않습니다.

## 처리 방식과 보호 장치

- 기본 확인 주기 300초, 변경 안정화 대기 60초. 로컬 이벤트가 발생하면 안정화
  주기 기준으로 더 일찍 확인합니다. 실제 스캔은 두 번 이상의 같은 목록을
  확인한 뒤 기존 스캔 큐에서 실행됩니다.
- 처음 켤 때 기존 파일은 기준 목록만 저장합니다. 현재 누락된 파일까지 반영하려면
  최초 한 번 수동 스캔하세요. 감시 시작 뒤 추가·수정된 폴더만 자동 스캔합니다.
- 파일 내용/압축 내부를 **감지 단계에서** 읽지 않습니다. 스캔 단계에서는 기존
  메타데이터/표지 처리 정책에 따라 원본 접근이 발생할 수 있습니다.
- 임시 확장자, 숨김 경로, 로컬 심볼릭 링크는 제외합니다.
- 스캔 완료 전에는 기준 목록을 갱신하지 않습니다. 큐 등록 전후에 재시작되어도
  미처리 작업을 복구하며, 스캔 중의 변경은 다음 비교에서 다시 반영합니다.
- 자동 삭제는 기본 OFF. ON이어도 원본 파일은 삭제하지 않고, 확인된 누락
  도서 레코드만 기존 휴지통으로 이동합니다. 기존 휴지통 보존/정리 정책은 그대로입니다.
- 전체 목록이 비거나 10개 이상이면서 절반 이상 사라지면 자동 반영을 보류합니다.
  실제 대량 삭제였다면 연결을 확인한 뒤 수동 스캔으로 처리하세요.
- 경로 접근 실패/권한 오류/조회 시간 초과 시 기준 목록을 보존합니다.
- 감시 조회는 별도 단기 프로세스에서 수행하고 120초로 제한합니다.
  파일은 경로별 최대 20만 개, Drive 깊이는 32단계까지입니다.
- 라이브러리 경로를 바꾸면 감시 설정도 다시 저장해야 합니다.

## 운영

기존 scanner_worker 프로세스 내 감시 스레드 하나가 실행됩니다. OS 파일 잠금으로
중복 감시를 막습니다. Linux/Docker 단일 서버 구성을 대상으로 합니다.
추가 포트/권한 또는 Docker privileged 설정은 필요하지 않습니다.

설정·기준 목록·미처리 상태는 기존 `/app/db` 볼륨의 `folder_watch.db`에 저장됩니다.
MariaDB 사용 시에도 이 파일은 필요하므로 `/app/db` 볼륨을 함께 보존해야 합니다.
DB 파일/잠금 파일을 외부에서 삭제해 초기화하는 방식은 권장하지 않습니다.

라이브러리 목록에서 최근 확인 시각과 오류를 확인할 수 있고, 큐에 등록된 작업은
기존 스캔 활동창에 **폴더 감시 스캔**으로 표시됩니다. 연결 오류는 네트워크·권한·
API 키·rclone 경로와 VFS 갱신 설정을 먼저 확인하세요.
